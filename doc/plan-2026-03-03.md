## 1. Критические ошибки

### 1.1. Отсутствие импорта `createElement` в `footer.js`

**Файл:** `src/app/components/footer/footer.js`

Функция `createElement` используется, но не импортирована. Работает только благодаря побочному эффекту в `element-creator.js`, который устанавливает `window.createElement`. Это ненадёжно — порядок загрузки модулей не гарантирован.

**Текущий код:**
```js
export function renderFooter(container) {
    const element = createElement('div', {
        className: 'gp__footer',
        text: 'footer'
    });
    // ...
}
```

**Исправление:** добавить импорт в начало файла:
```js
import { createElement } from '../../util/element-creator.js';
```

### 1.2. Дублирование ключа `preferences` в `en.js`

**Файл:** `src/app/locales/en.js`

Объект содержит два ключа `preferences` (строки 143 и 348). Второе определение перезатирает первое. В результате вызов `t('preferences.shortcuts')` в английской локали вернёт ключ как есть вместо перевода, потому что финальный объект `preferences` содержит только `{ dialog, general, common }`.

**Первое определение (строка 143):**
```js
preferences: {
```

```js
preferences: {
    dialog: 'Preferences dialog',
    general: 'General',
    common: 'Common'
}
```

**Исправление:** объединить оба объекта в один ключ `preferences`, включив все поля.

### 1.7. Невалидный параметр `minifyCSS` в `vite.config.js`

**Файл:** `vite.config.js`

Параметр `minifyCSS` не является валидным ключом конфигурации Vite. Корректный параметр — `cssMinify`, который уже присутствует.

**Текущий код:**
```js
build: {
    minify: true,
    cssMinify: true,
    minifyCSS: 'lightningcss', // невалидный ключ
    outDir: '../dist',
},
```

**Исправление:** удалить `minifyCSS` или заменить на корректную конфигурацию:
```js
build: {
    minify: true,
    cssMinify: 'lightningcss',
    outDir: '../dist',
},
```

При использовании lightningcss также необходимо добавить зависимость `lightningcss` в `devDependencies`.

## 2. Логические ошибки и недочёты

### 2.1. Кнопки Edit/Delete активируются до выбора строки

**Файл:** `src/app/app.js`, строки 101–106

При выборе элемента дерева с `template: 'preferences'` кнопки `btnEdit` и `btnDelete` получают класс `active` немедленно, ещё до того, как пользователь выберет строку в таблице. Это позволяет нажать «Изменить» или «Удалить» без выбранного элемента.

**Текущий код:**
```js
if (btnEdit){
    btnEdit.classList.add('active');
}
if (btnDelete){
    btnDelete.classList.add('active');
}
```

**Исправление:** не добавлять `active` при первоначальном выборе элемента дерева. Класс `active` должен добавляться только по событию `preferences-row-select`, которое диспатчится при клике по строке таблицы.

### 4.2. Введение паттерна EventBus

Сейчас компоненты обмениваются данными через `document.dispatchEvent(new CustomEvent(...))`. Это создаёт неявные зависимости, трудно отслеживаемые в коде.

**Рекомендация:** создать простой EventBus:
```js
// src/app/util/event-bus.js
class EventBus {
    constructor() { this.listeners = new Map(); }
    on(event, callback) { /* ... */ }
    off(event, callback) { /* ... */ }
    emit(event, data) { /* ... */ }
}
export const eventBus = new EventBus();
```

Заменить все `document.dispatchEvent` / `document.addEventListener` для кастомных событий на `eventBus.emit` / `eventBus.on`.

### 4.3. Утилита для localStorage с обработкой ошибок

**Файл:** `src/app/util/mainLocalStorage/shortcuts.js`

Операции с `localStorage` не обёрнуты в try/catch. В приватном режиме браузера или при переполнении хранилища они бросят исключение.

**Рекомендация:** создать обёртку:
```js
// src/app/util/storage.js
export function getJSON(key, defaultValue = null) {
    try {
        const raw = localStorage.getItem(key);
        return raw ? JSON.parse(raw) : defaultValue;
    } catch {
        return defaultValue;
    }
}

export function setJSON(key, value) {
    try {
        localStorage.setItem(key, JSON.stringify(value));
        return true;
    } catch {
        console.error(`Failed to save to localStorage: ${key}`);
        return false;
    }
}
```

### 4.4. Метод `destroy()` для ElementCreator

**Файл:** `src/app/util/element-creator.js`

Класс `ElementCreator` не имеет метода очистки. При удалении элементов через `innerHTML = ''` навешенные обработчики событий не снимаются, что может приводить к утечкам памяти.

**Рекомендация:** добавить метод `destroy()`, который:
- Снимает все обработчики событий
- Рекурсивно уничтожает дочерние `ElementCreator`
- Удаляет элемент из DOM

Для этого нужно хранить ссылки на обработчики в экземпляре:
```js
constructor(tagName, options) {
    this.element = document.createElement(tagName);
    this._listeners = [];
    this.applyOptions(options);
}

on(eventName, handler, options) {
    this.element.addEventListener(eventName, handler, options);
    this._listeners.push({ eventName, handler, options });
    return this;
}

destroy() {
    this._listeners.forEach(({ eventName, handler, options }) => {
        this.element.removeEventListener(eventName, handler, options);
    });
    this._listeners = [];
    this.element.remove();
}
```

### 5.2. Адаптивная вёрстка

Текущая верстка использует фиксированные ширины (`width: 432px`, `width: 90%`, `height: 90vh`), что делает приложение неудобным на мобильных устройствах и экранах с малым разрешением.

**Рекомендация:** добавить media-запросы для точек останова (768px, 1024px, 1440px). На маленьких экранах дерево можно скрывать за сайдбар-кнопку.

---

### 5.3. Доступность (a11y)

Текущие проблемы:
- Нет атрибутов `role` и `aria-*` на интерактивных элементах (дерево, таблица, модалка)
- Кнопки в header — `<button>` без `aria-label` и `disabled`
- Табы в модалке — `<div>` без `role="tab"`, `role="tabpanel"`, `aria-selected`
- Нет обработки клавиш (Enter, Escape для модалки, стрелки для навигации по дереву)
- Нет focus-trap для модального окна
- Дерево: элементы не имеют `role="treeitem"`, `aria-expanded`

**Рекомендация:**
- Добавить `role="tree"`, `role="treeitem"`, `aria-expanded` для дерева
- Добавить `role="dialog"`, `aria-modal="true"` для модалки
- Добавить `role="tab"`, `role="tabpanel"` для вкладок
- Реализовать закрытие модалки по Escape
- Добавить focus-trap при открытии модалки

---

### 5.4. Неконсистентное именование CSS-классов

Используется смешение подходов:
- BEM: `preference__settings-data`, `preference__modal-header`
- Без BEM: `btn`, `button`, `active`, `tab-buttons`, `tab-content`
- Глобальные имена: `title`, `close` (внутри `.preference__modal-header`)

Классы `title` и `close` слишком общие и могут конфликтовать.

**Рекомендация:** привести все классы к единой нотации BEM. Например:
- `title` → `preference__modal-title`
- `close` → `preference__modal-close`
- `btn` → оставить как утилитарный класс, но чётко задокументировать

**Рекомендация:** импортировать через `@use 'development' as *;` или использовать `@forward`.

## 7. Незавершённый функционал

### 7.1. Реализованы только shortcuts

Из 8 типов preferences (Shortcuts, Environment, Files, Folders, Registry, Network Shares, Drive Maps, Ini Files) реализованы только Shortcuts. Для остальных типов:
- Нет шаблонов форм (`preferences-template-*.js`)
- Нет таблиц (`preferences-table-*.js`)
- Нет логики сохранения/загрузки из localStorage
- Элементы дерева не имеют `name` (см. п. 1.6)

**Рекомендация:** для каждого нового типа создать:
1. Шаблон формы: `preferences-template-{type}.js`
2. Таблицу: `preferences-table-{type}.js`
3. Модуль localStorage: `util/mainLocalStorage/{type}.js`
4. Добавить `name` в `tree-view-preferences.js`
5. Добавить ветвление в `app.js` для рендеринга нужного шаблона

---

### 7.2. Разделитель (divider) в preferences не ресайзится

Внутри `gp__preference` есть элемент `preference__divider`, визуально похожий на ресайзабельный разделитель (имеет `cursor: col-resize`), но на нём нет обработчика перетаскивания.

**Рекомендация:** либо добавить функциональность ресайза (повторно использовать `resizable.js`), либо убрать `cursor: col-resize`, чтобы не вводить пользователя в заблуждение.

---

### 7.3. Нет навигации / роутинга

SPA-приложение не имеет системы маршрутизации. При перезагрузке страницы всегда отображается исходное состояние.

**Рекомендация:** рассмотреть добавление простого роутера на основе `hash` или `History API`:
- Сохранять выбранный элемент дерева в URL
- При загрузке страницы восстанавливать состояние из URL

---

### 7.4. Нет кнопки сохранения и экспорта данных

Данные хранятся только в `localStorage`. Нет возможности:
- Экспортировать настройки в файл (JSON/XML)
- Импортировать настройки из файла
- Отправить данные на сервер

**Рекомендация:** добавить в footer кнопки «Экспорт» и «Импорт». Для экспорта можно генерировать JSON-файл через `Blob` + `URL.createObjectURL`.

---

### 7.5. Нереализованные элементы header

Header содержит пустые блоки:
- `.gp__search` — нет поля ввода и логики поиска
- `.gp__nav` — нет элементов навигации

**Рекомендация:** либо реализовать поиск по дереву и навигацию (вперёд/назад/вверх), либо убрать пустые блоки, чтобы не занимали место в layout.
